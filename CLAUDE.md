# train-map: notes for Claude

Dylan's personal project: historic passenger timetables (starting with the April 1971 *Official Guide of the Railways*) are entered in the **Timetable Desk** (a claude.ai artifact app), and an **ArcGIS map** animates the trains along historic rail lines. Personal project, not PTNY work.

## Layout

| Path | What it is |
|---|---|
| `index.html` | The train map, hosted on GitHub Pages (built; don't edit by hand) |
| `scripts/` | Modern-timetable (GTFS) fetch and build scripts for the map |
| `desk/src/page.html`, `desk/src/core.js` | Timetable Desk source (core.js holds parsing: times, marks, stop merging) |
| `desk/map-template/` | Map source (`page.html` + `core.js`): used for `index.html` and embedded in the Desk for its **Map** download button |
| `scripts/build_map.py` | Builds `index.html` from the map source plus a Desk export (CSV + railroads JSON); also copies the core to `scripts/map-core.js` for the GTFS job |
| `desk/build.py` | Builds `desk/dist/timetable-desk.html` (the page that gets published) |
| `desk/stations.json` | Station list the Desk falls back to (an export of the ArcGIS stations layer) |
| `desk/test/` | `mock.js` (in-memory stand-in for the artifact database), `smoke.js`, `fake_geo.js` |
| `notebook/` | ArcGIS Online notebook that checks rail lines (read-only Steps 1–6; Step 8 writes) |
| `docs/HANDOFF.md` | Background and decisions so far |
| `TODO.md` | Flagged for the next map update |

## Changing the Desk

1. Edit `desk/src/page.html` or `desk/src/core.js`.
2. `python3 desk/build.py`
3. `node desk/test/smoke.js [seed.json]` and check it says "no page errors". The seed is a database download (`{"documents": {...}}`), kept out of git as `desk/test/seed.json`. Chromium is preinstalled; don't run `playwright install`.
4. Before publishing, read `presence/desk` with ArtifactData (get). If `dialogOpen` is true and `at` is within the last 2 hours, Dylan has a pop-up open: don't publish (or write data); tell him it's ready and wait until he says go or the flag clears. Building and testing locally is always fine.
5. Publish `desk/dist/timetable-desk.html` with the Artifact tool to the Desk's URL: https://claude.ai/artifact/5Q5YhkF8LaqtskkSX1gTBe (keep its capabilities: db, downloads, user).
6. Commit the source and the built file together.

## Changing the map

1. Edit `desk/map-template/page.html` or `core.js`.
2. Get a fresh Desk export: read `sources/og-1971-04/trains`, `.../tables` and `railroads` with ArtifactData (out_dir), make a seed, then run the built Desk with `desk/test/mock.js` in Playwright and call `__deskHook().buildCSV()` and `.rrList()`.
3. `python3 scripts/build_map.py export.csv railroads.json "Month D, YYYY"` writes `index.html`.
4. Test by loading `index.html` in Playwright with `js.arcgis.com` routed to `desk/test/fake_geo.js` + `desk/map-template/stub.js`.
5. Rebuild and republish the Desk too (it embeds the map template), then commit both.

Don't rebuild the map per table (Dylan, Nov 20): enter a guide's tables as data only, and at the end of the guide add its `DATE_SHIFTS` rules in one change, rebuild `index.html` and the Desk, and publish. Without a database dump tool, the authoritative export is the Desk's own Home → **Download map with today's entries** (the same page `build_map.py` writes): ask Dylan for it and commit it as `index.html`.

Map behaviour to keep: the date (first of the guide's month by default) drives the weekday; alternate-day service, one-off dates and the PC Table 3 April 25 time change (`DATE_SHIFTS` in core.js) depend on it.

## The Desk's data

Stored in the artifact's database (edit with the ArtifactData tool, same URL). One source (guide) per Desk:
- `sources/og-1971-04/tables` and `sources/og-1971-04/trains`; `railroads` (global identity: `abbrev` the code on tables, short name `common` (what the railroad itself went by), `nickname` (nicknames and slogans, e.g. Skunk Train), business name `name`, other names, `chartered`, `from` (began operating) and `to` for the whole railroad, `periods` `[{name, chartered, from, to}]` for its formal names over time (the guide's date picks the name shown and exported), `rootFrom` for a separate predecessor company, `intercityEnd` and `passengerEnd` (all passenger service, incl. commuter and mixed; before the guide's date means freight only for that guide) (the Railroads page hides ones not running on the guide's date, and can hide mixed-only ones), map color and basis, predecessors/successors, parent, HQ, lines served); `sources/og-1971-04/rrpages/<railroad id>` (a railroad's section in that guide: offices (one field since Nov 22, other offices merged in), route miles, subsidiaries, page numbers, common notes (the old general-equipment field was merged into them), and `lines`: `[{tableNo, miles, from, to, stations: [{miles, name, city, state, stationId?}]}]`); `newstations` (stations added in the Desk with temporary NEW-#### ids); `stationfixes/<StationID>` (corrections flagged for the ArcGIS layer: corrected `name`/`town`/`state`/`tz`, `was`, `note`; the Desk shows them already); `stationlists/current` (an imported station CSV).
- Train documents are stored compact: blank stop fields are left out, so scripts must tolerate missing fields.
- Batches: up to 50 writes, each pinned with `if_version`. Dylan wants few approval prompts: one batch per table where possible.

## Stations

- ArcGIS layer `Historic_Passenger_Stations` (key `StationID`). New stations: `StationID` = `"STN-" + Text($feature.OBJECTID, "00000")`, `StationLabel` = `Name (Town, State)`.
- After adding stations in ArcGIS: export the layer to CSV, load it in the Desk (Stations → Replace the station list), then swap each NEW-#### station for its real one in the same dialog.

## Entry conventions (agreed with Dylan)

- A pool train run under two railroads' numbers (UP 457 = BN 337, Portland–Seattle) is one record with `alsoNumbered` ("BN 337"); Add trains and the train list find it by either number.
- The Trains list is every train by railroad, in number order; a train's page has ← Previous, Next train and Next to review (next not marked Done), all in that order. A repeat column (`copyOf`) takes its status from the train it repeats.
- Seasonal schedules (CN Table 1: summer and winter Super Continental timings) are separate runs (`notSame`) whose frequency carries the dates from the first station: "Daily, June 16 to September 9" or "Daily until June 15 and after September 9". The map's `parseService` reads both forms (`season`) and runs each train only on its dates.
- Canadian tables print 24-hour local clock time: enter it as HH:MM. CN Table 1's ■ (add one hour February 1–April 24 and after October 30) and its daylight-time summer are map rules in `DATE_SHIFTS` (map core), like PC Table 3; a winter section that runs on as another train (No. 3 Toronto–Capreol into No. 1) is its own train with `col` on the main train and a through-car link.
- CN's eastern tables (4–22) print the February winter schedule in standard time (A.S.T./E.S.T.). Dylan's reading: the trains kept those clock times under daylight time, so `DATE_SHIFTS` runs them an hour earlier (standard) from April 25 to October 30; Table 10's z (+15 min June 26–Sept 9) is a rule too. A column headed with a season ("Until June 25 and after September 9") carries those dates in its frequency: the Guide prints only the winter schedule. The Chaleur proper is Nos. 16/17 (page 509, not in the timetables); 119/118 are Gaspé connections at Matapedia.
- Canadian National and Grand Trunk Western share CN's pages ("Canadian National—Grand Trunk"). Trains and tables in the U.S. are GTW (Table 19, Detroit–Durand–Chicago); a train crossing the border (the Maple Leaf, 158/159) changes from CN to GTW at Sarnia/Port Huron. GTW Table 19's a (Michigan times printed for summer: add one hour February 1–April 24 and after October 30) and the Indiana/Illinois daylight-time summer are `DATE_SHIFTS` rules; South Bend is printed in Eastern time. On CN Table 21 the Maple Leaf is two records with one number: CN 159/158 Toronto–Sarnia and GTW 159/158 Port Huron–Chicago, linked as through cars (Sarnia ↔ Port Huron); Table 21's ♆ is the same rule as Table 19's a. Windsor–Detroit buses go in train notes. Table 22's Northland is split the same way (Dylan, Nov 17): CN 87/88 Toronto–North Bay, Ontario Northland 187/288 North Bay–Cochrane (as printed in its column), CN 87/88 again Cochrane–Kapuskasing (second records, `notSame`), linked as through cars; the other ONR trains on Table 22 are entered under ONR, and bus columns go in the table notes. Tables 23–27 use Table 1's daylight-time reading (Manitoba and B.C. only). Algoma Central (page 523, October 1970, Eastern Standard time) uses the eastern-table reading too (`DATE_SHIFTS` by the table's title, since it has no number). Northern Alberta (page 522) needs no rule: Alberta and the B.C. Peace (printed M.S.T.) had no daylight time in 1971. A freight-only line printed as a station list (NAR McLennan–Hines Creek, ACR Hawk Junction–Michipicoten) goes in the railroad section's `lines` with `freightOnly: true`, not as a table or new stations.
- A transfer train printed in another train's column (NY&LB 3602 → 3704, "a" passengers transfer at Rahway; Dylan, Nov 27) runs to or from the transfer station so the map draws it there: its Rahway stop takes the other train's printed Rahway time (arrival = that train's departure, or departure = its arrival), noted on the train, with conn links on both.
- Weekday service is "Monday through Friday"; holidays are ignored. Alternate-day service: "Alternate days (from Apr 1, 1971)".
- When two tables disagree, use the more recently dated table and note it on the train; a disagreement that's in the Guide itself is marked as a known inconsistency. With no newer dated table, a numbered table wins over a condensed one. The Whole run does this itself (`prefer` in `tzOffFn`, used by `mergeStops`) for times; for a different station (PC 180/186 Grand Central on Table 12 vs Penn Station on Table 14) mark the older table's stop Table only (`disp`).
- Bus connections printed in a train's column (Kalispell ▲, Helena "a", Tacoma ♮) go in the table notes, not as stops.
- Through cars (cars run through) are kept separate from connections (passengers change). Links go on both trains.
- Trains with no equipment printed carry "Coaches" ("Coaches only"). Equipment endpoints go in From/To; a dash means both directions.
- Timing, schedule and transfer marks go in marks; baggage-only symbols go in notes.
- A mark that changes a time on certain days ("On Sundays operates 7 minutes earlier") means a separate run on those days, entered as its own train, not a change to this one.
- Trains of railroads with no tables yet are "Future railroad" placeholders and aren't flagged as problems.
- Mixed trains (passengers and freight) get the "Mixed service" tag. They carry no equipment unless the Guide prints some (no "Coaches" default).
- A table's **Service** (Edit table; `service`, Dylan, Nov 24): passenger trains (default), `commuter` (suburban/commuter: stations only, no train detail, e.g. PC Tables 17–21 and 35–40 in Nov 1970) or `freight` (freight only: stations only). Stations-only tables take their stations as grid rows from the station layer and no trains, so an empty train list isn't flagged; Home tags them.
- Condensed tables often print no date; a missing date on a condensed table isn't a problem.
- A column headed "Arrive" (PC Table 15: Baltimore, Capital Beltway, Washington southbound; Newark, New York northbound) is entered as arrival times; "– –" in a column means no stop (Dylan, Nov 23).
- A stop printed with a mark but no time ("f –", a flag stop) is entered with the mark only (type "f" in the cell); it isn't flagged as missing a time.
- Equipment with a blank From/To runs the whole train: the Desk fills in the train's first and last stations when you move to another table.
- Short name (`common`, Dylan, Nov 22) keeps "Railroad"/"Railway" but not the business form: "Bangor and Aroostook Railroad" (business name `name`: "Bangor and Aroostook Railroad Company", as Dylan enters it, with "Company", "Inc." etc.). The name without "Railroad"/"Railway" goes in `nickname` only where there's evidence it was widely used. Use that form for any railroad Claude adds. There's no separate Service field: the kind of railroad is `rrType` (Passenger, Commuter, Freight, Terminal…), and freight only in a guide is that guide's `freightOnly` (old `kind` values are still read).
- A railroad keeps one short name across renamings and reorganizations: each formal name is a period on the same record (D&H: Canal Company 1823–99, The D&H Company 1899–1930, Railroad Corporation 1930–68, Railway Company 1968–). Separate railroads that merged in go under Formed from / `rootFrom`. Chartered and began operating are kept apart. Mixed-only railroads get a neutral gray (#8C8F94) on the map.
- A railroad's page has a Railroad tab (identity, all guides) and one tab per guide (that guide's section, lines, consist); links from Home and tables open the guide tab.
- Ownership (Dylan, Nov 27): a railroad record's `owners` `[{rr: <railroad id>, from, to, note}]` (Railroad tab → Ownership), one row per owner and period; joint ownership is several rows (PRSL: PRR two-thirds to Feb 1, 1968, then PC, and Reading one-third). Subsidiaries are worked out from the other records' owners: listed on the owner's Railroad tab, and on guide tabs for the guide's date ("Owned or controlled by … · Subsidiaries: …"). The free-text `parent` field is now Ownership notes. A subsidiary with its own listing is its own record (L&NE: CNJ subsidiary, freight only).
- System maps (Dylan, Nov 27): pictures (or PDFs) uploaded on a railroad's guide tab go to the artifact's assets (`assets` capability) and are listed on its rrpages doc as `maps: [{asset, url, type, name, caption, page}]`; removing one deletes the picture unless another guide's section uses it. Not analyzed.
- Next/Previous table follow the Guide's page order across railroads; tables are grouped under their railroad in the table picker, and each table links to its railroad's section for the guide.
- Tables can have no number and no name (common on small and freight lines); they show as "Name (no number)", or by their first and last stations ("Reader – Waterloo (no number)").
- Freight-only railroads are entered on Railroads → **Freight-only sheet**: one row each (pages, name as printed, code, type, where it runs, states, route miles), all by keyboard (Tab across, the row stays put; Enter or Tab past the last box starts the next). `rrType` flags the kind of railroad (Terminal, Switching, Freight… or any typed value; commas for several). Name, `geography` and `states` go on the railroad record; `pages`, `miles` and `freightOnly: true` on its rrpages doc for the guide. The sheet also lists railroads marked freight only or whose passenger service ended before the guide's date.
- Home lists only railroads with passenger trains: a railroad freight only in that guide with no trains is left off. A freight-only railroad's station lists (BAR Tables 2–3) are lines on its guide tab, not tables.
- Route miles (Dylan, Nov 22): a section's `lines` can hold several lines for one table number (BAR Table 3's branches), each with an optional `name`; `milesFromLines: true` makes `miles` the sum of the lines. On the Freight-only sheet, Σ edits those same `lines` (name, from, to, miles) and ticks `milesFromLines`, so they show on the railroad's guide tab; a sum typed in the miles box (12.4+3.1) becomes unnamed lines when it has none (`milesParts` is the old form, read only to fill Σ). Only the railroad's own track counts (B&LE: not its Union Railroad trackage). A branch whose first station isn't at 0 is counted from its junction: use its last figure.
- **Tables and lines…** (Dylan, Nov 22) on a railroad's guide tab is one sheet for its section: one row per line (Page, Table, Table name, Line or branch, From, To, Miles; ＋ adds another line under the same table). With "Freight only in this guide" ticked the tables are kept only as lines (`tableNo`, `page`, `tableTitle` on each line; no timetables, no dates) and empty timetables already entered for them can be removed; otherwise tables not entered yet become timetables (date and zone from their first row). Saving ticks the route-miles sum when miles are entered. A **Service** column (Passenger / Commuter / Freight; the table's `service`, shared by its rows) is on this sheet and on Add tables; a new row takes the service, page and zone of the row above, and Tab out of a row's last box moves to the next row, adding one at the end (Dylan, Nov 27). Lines tables (guide tab, the sheet, station lists) move with ↑/↓/Enter and ←/→ at a box's edge; **Fill blanks from table names** (`guessLine`) fills only empty line name / From / To from the table's title ("Main Line - A to B", "X Branch. A - B", "A-B"; three points: first and last; no explicit name: the title as printed). Records shows the railroad list above the record, one tight row per railroad (details to the right of the name), both full width. Freight only and `noTimes` exclude each other: marking a railroad freight only (checkbox, sheet, or a copied section for a railroad freight only on the guide's date) clears `noTimes`.
- A railroad's guide tab has ← previous / Next in the Guide → (Guide order by first page; skips freight-only ones when Records' "Hide freight only" is on) and a button per timetable of that railroad in the guide. A station list printed without times (LIRR Table 1: miles from Penn Station and frequency of service, Apr 1971 and Nov 1970) is a line on the guide tab whose stations carry `freq` (as printed: "½ hr", "(c)") and `note`, matched to layer stations where they exist; bus-only stops are noted, not mapped.
- Each railroad's pages in a guide go in its section's `pages` ("140–143"): they set its place in Guide order (Railroads page "Guide order", Home's next railroad, a new table's page). `noTimes` marks a railroad with passenger service that prints no timetables in that guide (its trains show "No timetable" instead of waiting to be entered).
- One train printed as two (Santa Fe 17/18: The Super Chief and El Capitan ran combined but the Guide prints two columns and a condensed table for each) is one train record with both `names` ("The Super Chief / El Capitan"), so it's one train on the map. On a table printing both, the second column is a repeat column (`copyOf`) headed with its own name: Add trains "17 - El Capitan" → add again as a repeat column. Add trains matches a typed name against any of a train's names; a number typed twice ("17 - El Capitan, 17 - The Super Chief") becomes the train plus a repeat column, and the column's printed name is its `shownName` for that table. Two genuinely different trains with one number are separate records marked `notSame` (the map export then adds their names to the run id). A train printed twice with other days or stops is a second appearance (`setupOf`).
- A table row can carry its own `tz` (Dodge City on AT&SF Table 3: Central arriving from Chicago, Mountain going west); it beats the station's zone. Set it from the station's row dialog.
- A connection printed inside another train's column (AT&SF 201-200 La Junta–Denver in No. 18's columns) is its own train with `col` (that column's train), `dir` and `onlyRows` on the table; for a second column of the same train, a repeat column of the connection points `col` at the repeat column.
- A sign meaning "this time is on another train" (AT&SF Table 4: □ On Train 23 Barstow to Los Angeles, in No. 1's column) isn't a stop of the column's train: it's a repeat column of the other train with `col` (the column's train), `onlyRows` and `cellMarks` `{rid: mark}` (the marks as printed there), plus a connection link on both trains.
- Bus legs aren't stops. A connection that changes stations by bus (SP 98 at San Francisco to SP 12 at Oakland) is a link with `otherStationId`.
- A table printed as side-by-side panels (AT&SF Tables A and C: Westbound No. 17 | Eastbound No. 18) keeps one row list: a section line with `panel: true` starts the next panel, and a section line's `label` is its heading ("Westbound—No. 17—The Super Chief", "Connecting service"). Set both from the ✎ on a section line in the grid.
- The Trains page opens a train on its **Whole run** (combined from all its tables, marks spelled out as words); a table tab switches to entering that table's stops. Each table's stops are combined in row order (the way most of them read), and each stop lines up its day with the same station on other tables, so stops entered at different times or summary rows ("Lv. Chicago" at the top of Table 6) don't scramble the run. A train's own data is what it actually ran: its whole run is in travel (time) order whatever order the tables print or list stops in; the table with the most times sets the days, and an arrival row plus a departure row for one station are one stop of the run. Tables stay as printed.
- One number printed twice with other days and times (BN 9 Afternoon Zephyr: daily except Fridays and Sundays at 12:30 pm, and Fridays and Sundays at 4:40 pm) is two runs: Add trains → type the number → "add again as a separate run". They're separate records marked `notSame`; labels and the map's run id tell them apart by their days when the names match.
- Stations with no timed stop aren't entered (Dylan, Nov 20): no NEW station for a row where no train has a time, including rows printed only as flag stops with no time ("f –"); drop the row and list the names in the table notes. A "f –" stop at a station that is entered keeps its mark-only stop.
- Ontario Northland records carry ONR's own numbers (Northland 87/88, Englehart–Noranda 83/84, Porquis–Timmins 185–188); CN Table 22's printed numbers are in `alsoNumbered`.
- Mexico, Central America and other out-of-scope lines are entered because they're in the Guide but left unmapped (their stations carry `country` and `unmapped: true`). Alaska rows use zone `AHT` (UTC−10). US tables (Alaska included) get no daylight-time rule.
- A section that runs on fewer days than the rest of its train (Southern Crescent New Orleans–Birmingham; SCL 5/6's alternate-day City of Miami and South Wind sections; PC 177 New York–Washington) is its own record printed in the main train's column (`col`, `onlyRows`), linked as through cars where it joins. `notSame` is always a list of the other records' ids, never `true`.
- Equipment: a train (connections included) with none printed is "Coaches only" unless its notes say otherwise; mixed trains carry none.
- A new guide starts with Railroads → **Pages from the index**: every railroad's pages for the open guide in one alphabetical sheet (the nearest other guide's pages alongside).
- Starting a guide from another (Dylan, Nov 21): Railroads → a railroad's guide tab → **Copy tables from <nearest guide>**: "Same table" copies a table and its trains as printed (to check against the book), "Start from it" copies them with the table's date cleared (to update). Tables and trains keep their ids across guides (`carriedFrom` on each), so trains running over several tables come together again and links, `col` and row ids still match. A table the other guide dates on or before this guide's date is shown as "likely the same".
- A table's **✓ Mark trains done…** (next to its status) marks every train on it Done at once: that table's entry is set complete, and a train becomes Done once all its tables in the guide are complete; it can mark the table completed too.
- **Pages and dates…** (Dylan, Nov 23) on a railroad's guide tab: one sheet of every timetable of that railroad in the guide (Table, Name, Trains, Page, Table date), by keyboard, saving only changed tables. Copied tables keep the section's first page and ("Start from it") no date, so fill them here. In a new guide, a mark that changes times on certain days (q "32 minutes earlier" on weekends) is the other-numbered run printed in the same column (PC 1358 → 1656 Sat./Sun.).
- A table's **Follow-up** (`followUp`, Edit table; Dylan, Nov 22) is something still to do on it: shown on the table's summary line (⚑ with Done to clear) and in Home's Needs a look; not copied to another guide. April 1971 PC tables get one when Dylan enters the November table's connecting trains that April lacks. Moving into a box by keyboard (Tab, Enter, arrows) selects its contents; a click doesn't.
- Finishing a guide: Trains → **Finish this guide…** marks every train with nothing real open as Done (time differences between tables don't hold one back), finishes every table, gives trains with no equipment "Coaches only" (or an identical run's cars), resolves links that only name a number, and turns "Except Sunday" into "Daily except Sunday".
- `db_write` `update` merges top-level fields only: writing `tables`, `stops`, `equipment` or links replaces the whole field, so always send the full current value.
- Trains with different numbers that run as one (BN 9, 25 and 31 Chicago–St. Paul; 8, 26 and 32 back) keep their own records and columns, with `runsWith` (the other numbers; "Runs combined with" on the train). The export marks the stops where their times match `stop_section` "shared" and fills `runs_with`/`run_lead` (the member with most stops leads); the map draws only the lead there, labelled with every number running ("31 / 25 / 9").
